# UI / UX 設計ガイドライン

- 更新日: 2026-11-19
- 状態: デザイン方針はユーザー確認済み。具体キット・画面設計は未確定。

## 1. 基本原則

**一般的なSIEM/NOC/業務管理ダッシュボードに自然に見える、情報密度と操作性を重視したUI。**

- 「AIが生成したような画面」の典型的特徴を避ける。
- **Bootstrap系の実績あるUIキットを第一候補**とし、標準コンポーネントを再利用する。
- ボタン・モーダル・フォーム・テーブル・通知・タグ・ページネーション等を無闇に自作しない。
- 文章は短く正確に。見出し、状態、数値、日時、操作結果を明快に示す。
- 奇抜な色・多すぎるアクセント色・意味のないグラデーション/発光・過剰な角丸/アニメーションを避ける。
- コントラスト・キーボード操作・レスポンシブを確保する。色だけで状態を伝えない。
- 日本語表示を基本に、表や単位が崩れない設計を考える。

## 2. UIキット候補

| 候補 | 特徴 | 評価観点 |
| --- | --- | --- |
| [Tabler](https://tabler.io/) | Bootstrapベースのすっきりした管理画面 | 第一候補 |
| [AdminLTE](https://adminlte.io/) | 伝統的な管理UI、テーブル・ウィジェット | 比較候補 |
| [CoreUI](https://coreui.io/) | Bootstrap系の管理用コンポーネント | 比較候補 |

採用は最新のOSSライセンス、標準パーツの数、カスタマイズせず使える率、チャート/テーブル統合、保守性、依存関係の軽さで決定する。

## 3. レイアウト案（統合トップ）

- **左:** 固定サイドバー（Overview、Vulnerabilities、Threat Signals、Profiles、Assets、Settings等）
- **上:** ヘッダー/検索/アカウントメニュー/最終更新時刻/全体取得状態
- **中央:** 計数カードは最小限、詳細はテーブル中心
- **主要2領域を明確に分離:** 
  - **Global Threats:** 全世界の急浮上・悪用確認・今後7日の注目度予測
  - **My Environment:** 全案件横断の影響候補・未対応/要確認・案件ごとの状況
- 詳細へ進むと根拠・ソース・時系列・資産評価・修正履歴を確認できる。
- 案件ごとのビューは選択UIで切り替え、全案件横断も選択可能とする。

## 4. 表示と色の規約案

| 用途 | 表現 |
| --- | --- |
| 重大/対応優先 | キット標準のDanger/赤系 |
| 要確認/警告 | Warning/黄〜橙系 |
| 成功/対処済み | Success/緑系 |
| 情報/参照 | Info/青系 |
| 無効/補助情報 | Secondary/グレー系 |
| 未確認情報 | 専用ラベルと本文の根拠欄で「未確認」を明示 |

色は**重大性/状態の意味が一貫**する場合のみ使う。何でもカラフルなカードで囲わない。ライト/ダークモードは標準テーマの機能を利用し、初期の見た目の好みをロジックに埋め込まない。

## 5. 一覧/詳細の最低表示情報

### 一覧

- 識別子（CVE番号または暫定Threat Event ID）
- 簡潔なタイトル、対象製品
- CVSS/EPSS/KEVの有無（不明は不明として表示）
- 直近の変化、SNS等の観測数/注目度（収集範囲を考慮）
- 予測トレンド（24h/7d/30d。未解析と失効を区別）
- 公表時刻/最終観測時刻
- 自分との関連と対応状況（認証済み個人表示のみ）

### 詳細

- 原文への参照と複数ソースの整合/相違
- 確定情報と未確認情報の区別
- 数値指標とLLMの説明の区別
- 予測根拠、作成時刻、検証状態
- イベントタイムライン
- 案件/資産に関係する場合は個別評価・対応履歴（非公開）

## 6. レビュー時のチェック

- [ ] キット標準部品で置換できる独自コンポーネントがないか
- [ ] 意味のない装飾/キャッチコピー/説明文がないか
- [ ] 画面を開いた時に重要項目と現在の未対応がすぐ分かるか
- [ ] 値が欠損・古い・未解析の場合、誤って正常と見えないか
- [ ] ダーク/ライトのコントラストと文字サイズが読めるか
- [ ] 表の列幅・長いCVE名・日本語/英語の混在・小さい画面でも破綻しないか
- [ ] グローバル脅威と自案件の状態が視覚的・論理的に混在しないか
- [ ] UI上のLLM評価が「確定情報」と誤認されないか
